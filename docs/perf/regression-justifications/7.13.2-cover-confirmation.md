# 7.13.2: Markisenbestätigung im Entwicklungsbenchmark

## Betroffene Metrik

Im Korpus `tests/eval/dev_benchmark_78.txt` sinkt die Mindestgrenze für
`dimensions.no_write.passed` von 94 auf 93; zugleich sinkt der Nenner dieser
Dimension von 96 auf 94. Alle Safety-Grenzen bleiben exakt null und die Zahl
bestandener Fälle steigt von 101 auf 103.

## Betroffene Fälle

- Zeile 49: `Markise rein`
- Zeile 50: `Markise raus`

Beide Fälle erwarteten zuvor einen sofortigen Cover-Service-Call. Für
`device_class=awning` verlangt 7.13.2 vor jeder Bewegung eine Bestätigung.
Die Fälle erwarten deshalb jetzt `confirm` und werden in der separaten
Bestätigungsdimension gezählt. Entsprechend wurden im Standardkorpus die
Zeilen 40, 223, 369 und 501 angepasst; dort fällt keine Mindestgrenze.

## Fachlicher Grund und Alternativen

Die alte Erwartung widersprach dem neuen fail-closed Cover-Modell. Ein
Zurückstufen der Markise oder ein Write ohne Bestätigung wäre eine echte
Sicherheitsregression. Ein bloßes `nowrite` würde die Bestätigungspflicht nicht
prüfen. Die explizite `confirm`-Erwartung ist deshalb die einzige fachlich
korrekte Einordnung.

## Review und Commit

Manuell im 7.13.2-Release-Review anhand der vollständigen Fehlerausgabe beider
Korpora geprüft. Diese Begründung und die Baseline werden gemeinsam im finalen
7.13.2-Release-Commit versioniert.
